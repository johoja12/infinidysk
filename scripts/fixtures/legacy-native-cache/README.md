# C# native cache interoperability fixture

This harness links the **unmodified 1.x** cache writer, filesystem anchoring, repair
ledger, multipart identity and MemoryPack models from a sibling checkout. Only
application telemetry and an unused navigation type are stubbed. It generates generic
synthetic bytes. It does not read production configuration or contact providers.

Use a read-only checkout of fork 1.x `9c104b59`. The default source directory is the
sibling `infinidysk`; override the MSBuild `LegacySourceRoot` property when building
elsewhere. Use .NET 10 and a new absolute destination directory:

```sh
dotnet run --project scripts/fixtures/legacy-native-cache -- /tmp/id-legacy-cache-fixture
export INFINIDYSK_LEGACY_CACHE_FIXTURE=/tmp/id-legacy-cache-fixture/receipt.json
cargo test -p infinidysk-import -p infinidysk-native-cache csharp --locked -- --ignored --test-threads=1
```

The three explicit interoperability tests check:

- Identical source generations from raw compressed blobs, multipart geometry/AES
  parameters, persisted multipart identity and the original per-article repair ledger.
- Actual C# sparse and chunked payloads, including a short last block and partial
  coverage, copied to the Rust format without modifying the original catalogue.
- Full C# file import with atomic source provenance, followed by cache import and
  read/seek verification through both delivery labels in the shared Rust VFS, with
  **no providers configured**. This test is separate from privileged kernel FUSE tests.

Ordinary Rust tests also exercise corrupt bytes, symlinked leaves, missing volume
markers, live owner locks and refusal of mismatched generations/sizes.

The encrypted fixture describes padded ciphertext but stores the final plaintext in
native cache, as 1.x does. These checks qualify cache reuse; they do not qualify a live
media decoder or unknown archive layouts.

## Rust writes read by the original C# implementation

Export new disposable sparse/chunked stores from the Rust writer, using a new
absolute receipt filename:

```sh
ID_COMPATIBLE_CACHE_EXPORT=/tmp/id-rust-cache-receipt.json cargo test -p infinidysk-native-cache --lib legacy::writer::tests::export_original_csharp_readback_fixtures --locked -- --ignored --exact
dotnet run --project scripts/fixtures/legacy-native-cache -- verify-rust /tmp/id-rust-cache-receipt.json
```

The verifier only accepts marked generated fixture roots. It reads every block
using the unmodified original C# reader, checks SHA256, deletes only disposable
catalogue coverage, and reconstructs coverage using the original scanner and the
Rust-written manifests/journals. It never targets production paths or providers.
Keep each fixture at its original absolute path and device/inode, including inside
a container. This qualifies storage readability; it does not migrate v2 jobs back
into a v1 application database. The explicit export retains its generated roots
for inspection; routine tests clean only their own disposable roots.

For actual NAS write/readback qualification, keep `TMPDIR` on local storage and
provide `ID_COMPATIBLE_NAS_ROOTS` as a JSON array of one to four absolute disposable
NFS directories, outside every production cache root. Each must contain a
`fixture-owner` file with exactly `generated-native-cache-write-tests`. Run the
ignored `legacy::writer::tests::export_nas_write_readback_fixtures` test with a new
`ID_COMPATIBLE_CACHE_EXPORT` path, then the same C# `verify-rust` command. Preserve
the identical absolute local and NFS paths in both containers. The test checks
concurrent sparse/chunked publication and restart readback; the C# verifier checks
all generated bytes and reconstructs coverage from their journals. It accepts the
separate payload root only with its own generated-fixture marker. These tests do
not inject NAS server failure or alter existing cache registrations or payloads.

## Interrupted eviction and v1 scanner behavior

Export new disposable sparse/chunked stores interrupted after v1 coverage is
withdrawn into `RetiredEntries`, with payloads still at their original paths:

```sh
ID_EVICTION_EXPORT=/tmp/id-eviction-receipt.json cargo test -p infinidysk-native-cache --lib legacy::writer::tests::eviction::export_eviction_interop_fixtures --locked -- --ignored --exact
dotnet run --project scripts/fixtures/legacy-native-cache -- verify-eviction /tmp/id-eviction-receipt.json
```

The original C# reader/scanner must not resurrect the retired entry. An unrelated
entry must retain its exact bytes. The verifier accepts only marked generated roots
and does not open production paths. The export retains its generated roots for
inspection. Rust process-death tests separately exercise eviction recovery.
