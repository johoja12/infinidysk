# Deploy the merged upstream sync to nuc-1

The parallel InfiniDysk instance runs in Docker Compose on `nuc-1`. Compose lives at `/opt/docker/infinidysk`; its override selects `local/infinidysk:<sha8>`. Persistent config is mounted from `/opt/infinidysk/config`, and the PostgreSQL container is `infinidysk-postgres`. Inspect the live Compose config and mounts before changing them; do not print secrets.

1. Fetch `origin/main` and verify the PR is `MERGED`. Record the exact merge commit and build from a clean checkout of that source tree (with `libs/rapidyenc` initialized). Confirm its tree matches the recorded merge commit. If `origin/main` advanced to a different source tree after this PR merged, stop deployment and report the newer work rather than overwriting it with this sync image. Read the version from `version.txt`; tag the image `local/infinidysk:<head-sha8>` and pass `NZBDAV_VERSION`, full `NZBDAV_COMMIT_SHA`, and `REPO_URL=https://github.com/johoja12/infinidysk` to `docker buildx build --load`. If the PR merge commit has the same tree as the PR head, the head SHA can identify the image; report that distinction.
2. Transfer the image to `nuc-1` with `docker save`/`docker load`. Verify the tag exists on the host before changing Compose. Record the currently running image and preserve it for rollback.
3. Before changing Compose, back up `/opt/infinidysk/config` and make a PostgreSQL dump on the host. Use SQLite online backups for live SQLite files, or stop their writers before copying them; a tar of live database files alone is not a consistent database backup. Verify SQLite integrity and that the PostgreSQL dump can be listed. Store both outside the config mount in a timestamped directory under `/opt/infinidysk/backups`; verify the archives and restrict their permissions. Do not expose database contents or credentials in output.
4. Read Smart Prefetch status through the authenticated `/api/prefetch` endpoint. Record whether it was already paused. If unpaused, POST `{ "operation": "pause-all" }` to `/api/prefetch/operations` and wait until no jobs are running. Keep credentials out of output and use the existing authentication mechanism. Do not replace the container while jobs are still draining. If rollout is abandoned before replacement, restore the prior pause state once the existing service is healthy.
5. Back up `/opt/docker/infinidysk/docker-compose.override.yml`. Re-read the running image and expected Compose tag immediately before switching; stop if another deployment changed them. Protected Compose configuration may require `sudo -n`. Replace only its expected current `infinidysk` image tag with the new one. Run `docker compose --env-file secrets/app.env config --quiet` from the Compose directory, then recreate only `infinidysk` with `up -d --no-deps --force-recreate`.
6. Wait for Docker health plus `http://127.0.0.1:3004/healthz`, `http://192.168.20.65:8080/health`, and `https://infin.sakhter.org/healthz`. Confirm the container reports the expected version and commit SHA. After health passes, resume Smart Prefetch only if this workflow paused it. If startup or health fails, restore the saved override and recreate the previous image only when the database remains compatible, verify rollback health, and restore the prior pause state. For destructive or irreversible migrations, establish a consistent data-restoration plan before rollout; reverting the image alone is insufficient. Report any incomplete recovery.

Keep the previous image and backups until the new deployment has been verified. Do not change the original NzbDav container or the rclone service as part of this sync.
