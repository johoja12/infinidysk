# Native cache catalogue recovery

Qualified source: `c237a355` on `feat/rust-v2-fork-migration`. This is local fixture
and kernel/browser evidence, not a production deployment or live NAS acceptance.

## Recovery contract

New final-media writes append checksummed, versioned recovery records after payload
sync and before catalogue publication. Records bind the folder ID, ownership marker,
device/inode, item/source revision, size, chunk geometry and block checksum. The
journal append lock covers only the small record; payload writes stay parallel.
Interrupted or unsynced journal tails can reduce recoverable coverage. Unrecorded
chunks never become coverage merely because their filenames or sizes look valid.

Normal startup still refuses unknown nonempty volumes. Explicit recovery mode can
reconstruct folder registration only from a matching owned Rust manifest and the
same physical directory. It acquires the existing volume lock and validates identity
before use. Recovery mode does not activate 1.x storage: use the verified legacy
copy importer into separate Rust folders first.

The admin recovery endpoint recomputes the key from the current source metadata and
trusted repair index. Each page verifies at most four blocks before publishing their
metadata. Timed-out physical I/O retains its guards and permits and cannot publish
late results. Cursor-based pages can resume after restart. Browsing retains at most
51 candidate names and bounds enumeration at 100,000 directory entries per folder.
A changed source revision or geometry is rejected. This restores the cache catalogue;
it does not reconstruct a lost main database or repair ledger.

Payload writes, warming and eviction are held in recovery mode. Incomplete cache
coverage remains unknown to automatic repair, rather than proving that no retained
copy exists. Newly reconstructed entries start pinned for review. Turn recovery mode
off and restart after inspecting coverage and retention. A completed pass means the
available records were checked; it is not a claim that every source byte was cached.

The setting is advanced-only, defaults off and requires restart. No new-install
wizard field or version increase is needed. No destructive database migration is
added; keep a `/config` backup before any upgrade or recovery operation.
