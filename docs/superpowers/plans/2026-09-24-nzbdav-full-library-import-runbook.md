# Mapped NzbDav Library Import: Production Run Plan

**Status:** Revised plan only. The attempted full-library preflight was stopped on 2026-09-24 before inventory, recovery, export, or submission. Its newly created backup and run artifacts were removed; the existing canary and older NAS backups were preserved. The currently installed CLI does not enforce mapped-only selection, so no bulk import may resume with it.

**Objective:** Import only NzbDav NZBs proven to belong to the currently mapped library into InfiniDysk. Create parallel `/mnt/plex2` and `/mnt/special2` links only for eligible mapped files, with at least 90% owned, exact-target, size-validated coverage of each fresh final mapped inventory. Keep NzbDav, `/mnt/plex`, and `/mnt/special` authoritative. Plex and Arr continue using their current paths.

| Legacy mapping root | Parallel validation root | Private artifact namespace |
| --- | --- | --- |
| `/mnt/plex` | `/mnt/plex2` | `plex/` |
| `/mnt/special` | `/mnt/special2` | `special/` |

The migration commands operate on one root at a time. Carry the source root with each `LinkPath` through inventory, package selection, plans, journals, and coverage; identical relative paths in the two roots are distinct links. A shared NZB payload may be imported once, then used by separately verified link plans for both roots. The current CLI does not provide that cross-root target reuse automatically, so duplicate legacy leaves remain a hold point until the workflow and tests support it.

This is the operator sequence for the [approved recovery design](../specs/2026-09-21-nzbdav-full-library-recovery-design.md), its [implementation plan](2026-09-21-nzbdav-full-library-recovery.md), and the [migration guide](../../guides/nzbdav-migration.md). Those documents define the package formats, commands, and safety checks; this plan records the current production starting point and the gates for a full run.

## Mapped-only selection contract

NzbDav records mapping in `LocalLinks`, one row per mapped file (`LinkPath`, `DavItemId`, `IsBroken`). A file is eligible only when its row is not broken, its path is strictly beneath **either** `/mnt/plex` or `/mnt/special`, and that exact path is a symlink into the NzbDav `.ids` tree whose **final ID component** equals the row's `DavItemId`. Match path components, not string prefixes such as `/mnt/plex-other`; assign each row to exactly one root. The `.ids` target has shard directories before the ID; do not require the ID immediately after `.ids/`. Missing, changed, duplicate, or mismatched rows/links are classified and reviewed, never inferred from names or counts.

The mapped file set is the authoritative source scope. A recovered NZB is eligible for package export only when strong article evidence connects it to at least one eligible mapped file; do not export unrelated retained history, orphan blob payloads, or NZBs that match only unmapped files. The catalogue may scan the blob tree to find evidence, but scanning does not authorize submission. The package's selected links must be a subset of the frozen mapped allowlist, and `export-batches` must fail closed if any release has no mapped selection. Recheck mapping membership and the original symlink immediately before each link apply.

**Mixed NZBs:** Import a whole NZB when it has both mapped and unmapped files, but select and create links in `/mnt/plex2` or `/mnt/special2` only for its mapped files, using the corresponding source root. The normal InfiniDysk import may create unlinked entries for other files in that NZB; record their count in the run report. Never treat those extra entries as mapped coverage or create parallel links for them. This is the operator-selected policy for this run.

**Implementation gate:** The legacy `inventory` command still reads filesystem `.ids` links and `DavItems` without joining `LocalLinks`; it remains suitable only for the bounded canary. Full recovery uses the new `mapped-inventory`, `verify-mapped-roots`, `apply-mapped-links`, and `mapped-coverage-report` commands. Build and install them from the merged, tested revision before another full run. The mapping reader must read `LocalLinks` and `DavItems` in one repeatable-read, read-only transaction; seal a root-qualified mapped allowlist and its digest in each inventory/master; and reject missing or changed provenance at export, apply, and final coverage. Shared NZB payloads or legacy leaves across roots remain a hold point until one-import target reuse with separate root-qualified link plans and ownership journals is implemented and tested. Test stale links, unmapped blobs, broken rows, sharded targets, mixed releases with unlinked imported entries, duplicate relative paths and `DavItemId`s across roots, target reuse, and mapping drift.

For coverage, report the total mapped DB rows, valid mapped source links, mapping conflicts, and out-of-scope filesystem links separately **for each root and combined**. Each root's 90% denominator is **all fresh final `LocalLinks` rows beneath that root**, including broken or conflicting rows as exclusions; do not make the percentage look better by dropping them from the denominator. Calculate combined coverage from the sum of both numerators and both denominators and require it to reach 90% too. The denominator is not all blobs, all history NZBs, or all `.ids` links found on disk. A source mapping conflict must be resolved or explicitly classified before the run advances.

## Boundaries and evidence

- The source database uses the SELECT-only migration role and repeatable-read read-only snapshot. The source blob tree, `/mnt/plex`, and `/mnt/special` are read-only inputs. The migration tool never writes to NzbDav, Plex, Arr, or the legacy library.
- Store run artifacts under `/opt/infinidysk-migration/full/<new-utc-run-id>` on the provisioned volume, mode `0700`; individual artifacts remain `0600`. Record SHA-256 digests, tool/image commits, configuration, and timestamps. Do not publish raw inventories, paths, NZBs, credentials, or article IDs in issues or PRs.
- InfiniDysk sees only the current checksummed package through `/config/migration-input/...:ro`. It does not receive the legacy database, blob root, or either source or parallel library root as a writable mount.
- Every new parallel link is create-only and journaled. Its exact target must be beneath `/mnt/remote/infinidysk/.ids/`; it must never target NzbDav. Preserve any pre-existing unowned file or link as a conflict for review.
- Every mapped source row gets one covered or exclusion classification in its own root. At least 90% of the fresh final mapped DB set in **each** root must be owned and validated in its paired parallel tree, including the delta pass; the combined ratio must also reach 90%.

## Execution sequence and hold points

### 1. Prepare capacity, backups, and a reproducible tool

1. Verify both services and rclone mounts, current app/tool revision, PostgreSQL and `/config` backups, legacy database and blob-tree backup or storage snapshot, and free space on both the run and backup volumes. Record checksums and a restore test for the backup set.
2. Freeze an operator record of the current 30-link `/mnt/plex2` canary, including the **current** naming-reimport journal and validation result. Re-run `validate-links` against that journal and check the existing source-name remediation. Inventory `/mnt/special` and perform its own 20–50-link canary before full import. Stop on a mismatched target, failed read, or unowned link; do not silently replace it.
3. Verify the merged mapped-only and two-root identity gates above, then pin one self-contained `NzbDavMigration` executable under `tools/<commit>` and record its digest. Its mapped inventory, root comparison, recovery, export, mapped apply, validation, mapped coverage, and rollback commands must match the selected backend. The currently installed `acb6f0ce` binary is **not** eligible for bulk use because it lacks the `LocalLinks` gate.

**Hold:** Do not start the full scan until the mapped-only and two-root CLI tests, backups, revision compatibility, canary validation for both roots, and artifact/backup storage have passed. The root filesystem remains nearly 90% used and is not the dedicated artifact volume required by this plan.

### 2. Inventory and recover without importing

1. Create a new private run directory with `plex/` and `special/` subdirectories. Run the revised single-root `inventory` once against `/mnt/plex` and once against `/mnt/special`, using the SELECT-only legacy connection and `/opt/nzbdav/config/blobs`. Freeze `LocalLinks` and `DavItems` in the same read-only source snapshot for each inventory, match every selected row to its current symlink and ID, and record root-qualified mapped allowlist digests, per-root and combined denominators, mapping conflicts, source inode/target snapshots, and `SHA256SUMS`. Compare duplicate `DavItemId`s and source targets across the two inventories. Stop on an unexplained mismatch or unresolved cross-root duplicate.
2. Run `catalogue-list` to freeze a no-follow blob input list shared by the two root-specific recovery passes. Run the resumable `catalogue-scan` with its SQLite database on local storage and checksummed immutable outputs on the provisioned artifact volume. Monitor disk headroom, scanner progress, legacy service latency, and errors. Resume only against the same frozen list; seal the catalogue only when all input files are classified. Catalogue contents are evidence, not the import selection.
3. Run the revised `recover-full --minimum-coverage 0.90` separately for `plex/` and `special/` over eligible mapped leaves only, while counting ineligible mapped rows as exclusions in each denominator. Check that recovered and excluded mapped rows sum exactly to each root's full mapped denominator. Inspect ambiguity, missing-article, corrupt/changed blob, and unsafe-ancestry samples without using filenames to turn an uncertain match into an exact one. Verify that every proposed NZB has mapped-link evidence and that no orphan-only release enters either master manifest. Check the combined recovery ratio too.

**Hold:** If uniquely recoverable article-backed links are below 90% in either root or in the combined inventory, stop before `export-batches`, package staging, or backend submission. Publish per-root and combined counts and failure classes, then plan a separate remediation. Do not lower the threshold.

### 3. Export and import bounded batches

1. After the dry-run gate, seal both root-qualified mapped allowlists and master manifests, then export deterministic, checksummed packages containing **only NZBs with eligible mapped files**. Default caps are 250 releases and 4 GiB NZB payload bytes per batch. Check projected total package bytes against available space before export; reduce caps if needed, without splitting a release. Compare every batch's selected mapped IDs and payload provenance with its sealed allowlist before staging; count any other files carried by a mixed NZB separately. Deduplicate a shared NZB by strong payload identity, retain both root-qualified link selections, and block a second submission until target reuse is proven.
2. Stage one completed batch at a time under the read-only migration input mount. In **Settings → System → Migration → NzbDav**, connect by digest, map only dedicated migration categories, scan, and resolve every blocking finding. Use one submit worker and queue depth five. Do not advance while another batch is active or unacknowledged.
3. Wait for terminal submission, then reconcile the same run to all-exact results. On timeout, inspect the persisted ledger before retrying; never start a duplicate run merely because a status request failed. Preserve package, run, and master digests.
4. Download and verify the complete plan bundle. Require selected = exact = actionable and recheck that every selected leaf remains mapped in NzbDav. Apply each root-qualified plan to its own pair: `/mnt/plex` → `/mnt/plex2` or `/mnt/special` → `/mnt/special2`, with target root `/mnt/remote/infinidysk`. Retain separate durable journals under `plex/` and `special/`. A shared imported target may serve links in both parallel trees only after exact correlation and both source checks pass. Run `validate-links` with bounded reads and `ffprobe` where suitable. Acknowledge the batch only after every selected mapped link validates.
5. Check service health, queue depth, disk space, NzbDav source snapshots, and both source/parallel mount pairs after each batch. Pause and preserve state on a failed submission, non-exact mapping, source drift, target-size mismatch, apply conflict, or provider instability. Repair and resume the same batch.

### 4. Delta pass and acceptance

1. Freeze fresh mapped `LocalLinks` inventories for both `/mnt/plex` and `/mnt/special`. Catalogue only new blob inputs and process newly mapped or changed eligible links through separate root-specific delta batches. Report removed mappings and deleted source links separately; do not automatically remove their parallel links.
2. Place each unmodified initial/delta master manifest in a private coverage directory **per root** and run the revised `coverage-report` against each final mapped source snapshot, its paired parallel tree, and its apply journals. Require **validated owned mapped links / all final mapped DB rows ≥ 0.90 for each root**, plus the combined ratio from both numerators and denominators ≥ 0.90. Investigate every `missing-parallel`, `wrong-target`, drifted, broken, or unclassified row; out-of-scope filesystem links never enter the denominator.
3. Independently audit that every `/mnt/plex2` and `/mnt/special2` target is an InfiniDysk `.ids` path, every target exists at the expected size, and no legacy target was substituted. Compare both source roots' inode/target snapshots for paths that did not change between the initial and final inventories; classify legitimate source drift separately.
4. Run bounded first/repeat throughput and 10/50/90% seek checks plus representative `ffprobe`/playback samples across direct, RAR, multipart, TV, movie, 4K, small, and large files. Record route and cache state with results; verify both NzbDav and InfiniDysk remain healthy.
5. Publish a sanitized operator result with per-root and combined initial/final mapped DB denominators, eligible and excluded counts, mapping conflicts, recoverable and validated counts, exact percentages, mixed-NZB unlinked entry counts, batch totals, performance findings, backup locations, and rollback journal IDs. Keep `/mnt/plex2` and `/mnt/special2` outside Plex and Arr. Consumer registration or cutover needs its own plan and explicit request.

## Recovery and rollback

| Failure point | Response |
| --- | --- |
| Inventory, catalogue, or recovery fails | Keep NzbDav authoritative; preserve the immutable input list and partial private catalogue, fix the cause, resume or start a new run ID as appropriate. No import has occurred. |
| Dry-run coverage below 90% | Stop before export/import; report exact exclusion classes and required recovery work. |
| Batch import or correlation fails | Pause the migration queue and retain the same package/run ledger. Reconcile or repair that batch; do not create links for non-exact rows or submit the batch again blindly. |
| Link apply or validation fails | Preserve the plan and journal. Resolve the conflict without overwriting an unowned path. `rollback-links` removes only still-matching links owned by that journal; it does not remove imported releases. |
| App/database regression | Stop further batches. Restore the verified `/config` and database checkpoints only through a reviewed recovery procedure; leave NzbDav, `/mnt/plex`, `/mnt/special`, Plex, and Arr unchanged. |

The exact CLI syntax and UI steps are in the [migration guide](../../guides/nzbdav-migration.md). Before executing this plan, replace the snapshot values above with a new signed run record and verify the chosen image/tool pair against the then-current `main` commit.
